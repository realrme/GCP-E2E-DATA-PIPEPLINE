Project Overview

What this pipeline does and why it matters

🎯
Business Goal
Transform raw grocery transaction data from a PostgreSQL source into clean, analytics-ready tables in BigQuery for business reporting and KPI tracking.
⚙️
Automated Scheduling
Apache Airflow orchestrates the entire pipeline on a daily schedule — zero manual intervention required from ingestion through to the gold data mart.
🔍
Full Observability
OpenLineage metadata events are pushed to GCP Dataplex, giving complete visibility into every data movement — from source Postgres to the final Gold layer.
🏗️
Infrastructure as Code
All GCP resources (BigQuery datasets, APIs, IAM) are provisioned and versioned via Terraform — reproducible across environments with a single command.
🧊
Medallion Architecture
Data flows through Bronze → Silver → Gold layers using dbt models, each adding a transformation layer: staging, star schema, and aggregate reporting.
🐳
Local Dev with Docker
The entire stack runs locally via Docker Compose with a seeded PostgreSQL source database, enabling full development and testing without cloud costs.

Step 1 — Data Ingestion

Batch extraction from PostgreSQL to BigQuery Bronze

# batch_ingest_postgres_to_bq

def _extract(engine, table):
    df = pd.read_sql_query(
        f'SELECT * FROM "{table}"',
        conn
    )
    return df

# Add metadata columns
df['_ingested_at'] = now
df['ingestion_date'] = now.date()

# Load to BQ with partitioning
job_config = LoadJobConfig(
    write_disposition=WRITE_APPEND,
    time_partitioning=TimePartitioning(
        field='ingestion_date'
    )
)
client.load_table_from_dataframe(
    df, bq_table, job_config
)
  • 📥
    Source Local Docker PostgreSQL container seeded with 1,980 grocery transaction records from CSV files.
  • 🏷️
    Metadata Stamping Each row is enriched with _ingested_at timestamp and _source_file audit columns.
  • 📊
    Partitioned Loading BigQuery table is day-partitioned by ingestion_date for cost-efficient query processing.
  • 🔭
    Lineage Emitted OpenLineage START and COMPLETE events are posted to Dataplex after every table load.

Step 2 — Medallion Transformation

dbt models build the Bronze → Silver → Gold data layers

🥉 Bronze Layer
bronze_transactions
stg_grocery_transactions
Staging model that cleans raw ingested data, casts types, and applies business naming conventions.
🥈 Silver Layer
silver_transactions
dim_customers
dim_products
dim_stores
fact_grocery_transactions
scd_customers [SCD Type 2]
Star schema with dimension tables and a central fact table. SCD Type 2 snapshot tracks customer history over time.
🥇 Gold Layer
gold_transactions
mart_sales_summary
Aggregated business mart joining facts with dimensions. Ready for BI tools and dashboards with pre-computed KPIs.
